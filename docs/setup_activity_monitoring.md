# Настройка мониторинга активности пользователей

## Обзор

Система мониторинга активности отслеживает:
- Сообщения в группе Telegram
- Реакции в группе
- Активность в боте (создание мероприятий, участие в них)

## Настройка

### 1. Установка дополнительных зависимостей

```bash
npm install telegram luxon input p-limit
```

### 2. Получение API ключей Telegram

1. Перейдите на https://my.telegram.org/apps
2. Создайте новое приложение
3. Получите API_ID и API_HASH

### 3. Настройка переменных окружения

Добавьте в ваш .env файл:

```env
# Telegram API для мониторинга активности
TG_API_ID=your_api_id_here
TG_API_HASH=your_api_hash_here
TG_STRING_SESSION=your_session_string_here
TG_TARGET_CHAT=your_group_chat_id_here
ACTIVITY_WINDOW_DAYS=30  # Опционально, переопределяет значение из конфига
```

### 4. Получение session string

Запустите скрипт для получения session string:

```bash
node telegram_login.js
```

Следуйте инструкциям:
1. Введите номер телефона (с кодом страны, например +7123456789)
2. Введите код подтверждения из Telegram
3. Если у вас включена 2FA, введите пароль
4. Скопируйте полученный session string в .env файл

### 5. Настройка cron задачи

Добавьте в crontab для еженедельного запуска:

```bash
# Запуск мониторинга активности каждую неделю в воскресенье в 03:00
0 3 * * 0 cd /path/to/your/bot && node activity_monitor.js >> /var/log/activity_monitor.log 2>&1
```

## Команды для администраторов

### Просмотр неактивных пользователей
```
/inactive
```

### Исключение пользователя из проверки активности
```
/exempt username
/exempt @username
/exempt telegram_id
```

### Включение пользователя в проверку активности
```
/unexempt username
/unexempt @username
/unexempt telegram_id
```

### Просмотр исключенных пользователей
```
/exempt_list
```

## Логика работы

### Критерии активности

Пользователь считается активным, если в течение указанного периода он:
- Отправлял сообщения в группе, ИЛИ
- Ставил реакции в группе, ИЛИ
- Был активен в боте (создавал мероприятия, участвовал в них)

### Настройка периода активности

Период активности настраивается тремя способами (по приоритету):

1. **Переменная окружения** (высший приоритет):
   ```env
   ACTIVITY_WINDOW_DAYS=45
   ```

2. **Конфигурация по окружению**:
   - `config/development.json`: 7 дней (для разработки)
   - `config/production.json`: 30 дней (для production)

3. **Значение по умолчанию**: 30 дней

**Примеры настройки в конфиге**:
```json
{
  "activity_monitoring": {
    "window_days": 30,
    "description": "Количество дней для определения активности"
  }
}
```

### Исключения

Пользователи с флагом `is_exempt_from_activity_check = true`:
- Никогда не помечаются как неактивные
- Не появляются в списке `/inactive`
- Не учитываются при подсчете статистики

### Обновление данных

Данные обновляются:
- Сообщения в группе: при запуске скрипта `activity_monitor.js`
- Реакции: при запуске скрипта `activity_monitor.js`
- Активность в боте: в реальном времени при создании/участии в мероприятиях

## Структура базы данных

Добавлены поля в таблицу `users`:
- `last_message_date` - дата последнего сообщения
- `last_reaction_date` - дата последней реакции
- `last_bot_activity_date` - дата последней активности в боте
- `is_active` - флаг активности (обновляется скриптом)
- `is_exempt_from_activity_check` - флаг исключения из проверки

## Безопасность

⚠️ **Важно**: 
- Никогда не делитесь session string
- Не коммитьте .env файл в репозиторий
- Храните API ключи в безопасности
- Регулярно проверяйте активные сессии в настройках Telegram

## Устранение неполадок

### Ошибка авторизации
1. Проверьте правильность API_ID и API_HASH
2. Пересоздайте session string с помощью `telegram_login.js`
3. Убедитесь, что номер телефона введен с кодом страны

### Ошибка доступа к группе
1. Убедитесь, что аккаунт является участником группы
2. Проверьте правильность ID группы
3. Убедитесь, что у аккаунта есть права на чтение истории сообщений

### Проблемы с базой данных
1. Убедитесь, что поля добавлены в таблицу `users`
2. Запустите миграцию базы данных при необходимости
3. Проверьте подключение к базе данных
